### Rule 4 — Free to Play, No Login, Web-Based

> "Game has to be accessible on web without any login or signup and free-to-play."

**Implementation Requirements:**
- ❌ No authentication wall of any kind
- ❌ No paywalls
- ✅ Hosted on Vercel (public URL, no login)
- ✅ Runs in-browser — Three.js, no Unity/native downloads

---

### Rule 5 — No Loading Screens ⚠️ HIGH RISK

> "NO loading screens and heavy downloads (!!!) — has to be almost instantly in the game."

**Implementation Requirements:**
- The game must be playable within **~1 second** of the page load.
- MIDI files must be loaded asynchronously, **after** the initial render.
- No heavy asset bundles in the initial JS payload.
- Audio files loaded on-demand (not at startup).

**Architecture Impact**: This rule drove `ADR-002` (no heavy framework) and `ADR-005` (object pooling). See `MEMORY.md`.

**Exception allowed**: "except maybe ask username if you want" — a lightweight name prompt is acceptable.

## 🌀 Optional: Vibe Jam Portal System

> "Make an exit portal in your game players can walk/fly/drive into — you can add a label like 'Vibe Jam Portal'."

This is **optional but recommended** — it adds the game to the Vibe Jam webring and increases discoverability.

### Portal Redirect URL

When player enters the portal, redirect to:
```
https://vibej.am/portal/2026
```

### Supported Query Parameters (outgoing)

```
https://vibej.am/portal/2026?username=player1&color=purple&speed=5&ref=algorhythm.vercel.app
```

| Param | Description |
|-------|-------------|
| `username` | Player's name |
| `color` | Player color (`red`, `green`, `yellow`, or hex) |
| `speed` | Meters per second |
| `ref` | URL of our game (for return portal) |
| `avatar_url` | (optional) Player avatar |
| `team` | (optional) Team name |
| `hp` | (optional) Health 1–100 |
| `speed_x/y/z` | (optional) Velocity components |
| `rotation_x/y/z` | (optional) Orientation in radians |

### Receiving a Portal Player

When our game receives `?portal=true` in the URL:
1. Skip start screens immediately — drop player directly into gameplay.
2. Read `?ref=` parameter to create a **return portal** so they can go back.
3. Use `?username=` and `?color=` to personalize experience.

Detection:
```ts
const params = new URLSearchParams(window.location.search);
const isPortalEntry = params.get('portal') === 'true';
const returnUrl = params.get('ref');
const username = params.get('username') ?? 'Player';
```
